# Feature and source matrix

The unreleased source consumes public SDK `0.3.0-preview.2` contracts over HUD API v3, with one SDK-owned session for game, panel, options and manager views. Production areas subscribe independently; player cards ignore pose updates, and only visible timed areas use the shared synchronized clock. The published 0.4.18 package remains API v2. The HUD renders supplied state; it does not calculate a second game state or collect CS2 payloads itself. Missing numeric values are `—`. Unknown enum values do not become an assumed known state.

The current source replaces 81 local weapon, grenade, status and killfeed SVGs with the [OpenHud reference icons](../LICENSES/OPENHUD-ICONS.md), with measured optical sizing. Existing SVGs remain for symbols not supplied by that reference, including flash assist and hostage rescue. The radar uses its existing assets.

Player portraits use the supplied local image first. Missing or failed portraits use one of twenty bundled CS2 agent images, selected by the player's actual CT/T side and observer digit 0–9. Every digit has a different agent on each side. Side/slot changes update the placeholder; newly supplied real portraits take priority. Unknown side/slot retains the previous final fallback (omission in live cards, monogram in presentation cards). These placeholders do not assert the player's equipped agent. See [agent sources and rights](../LICENSES/AGENT-PORTRAITS.md).

The optional Display checkbox **Nur Agenten anzeigen** (`display.agentsOnly`) suppresses all supplied player photos, including explicit spotlight references, while preserving their names and statistics. Turn it off to restore normal photo priority. Agent fallback remains active in both modes; team logos and sponsor images are unaffected.

Player portraits animate the explicitly supplied `Smoked`, `Flashed` and `Burning` conditions while data freshness is `Live`. Locally bundled Motion 14.5.0 controls interruptible intensities for procedural canvas geometry: dense overlapping smoke clouds with round puffs fly in from below and drift, flame contours deform with sparks, and a circular flash expands from the lower-left corner to cover the entire agent. Each effect uses the alpha channel, crop and position of the actually displayed image, including fallback changes. Transparent holes and margins remain untouched; opaque photos receive the effect across their opaque rectangle.

All smoke clouds start simultaneously at the same height below the avatar, with one shared linear progression over 3450ms. Different destination heights produce different speeds, with simultaneous arrival and no pauses. Clouds keep drifting and changing shape while active. Individual flames enter from below; they are never revealed by a rolling or moving clip boundary. Flash grows radially, then fades uniformly at its reached radius when cleared; reactivation resumes from the current radius and opacity. Smoke and fire keep moving while active and fly back below the portrait when cleared. Fire reaches one-third at its original speed (about 107ms), pauses for 250ms, then grows in one slow three-second surge (about 3357ms total). Their exit times remain 900/480ms, and flash remains 160/260ms. Motion starts each replacement tween from the current intensity, including reactivation during exit, without finishing a queued sequence. Hidden effects have no running frame loop. Death, stale data and removed portraits dispose animations immediately; player/image/round changes reset progress. Reduced-motion preferences show a static state with immediate status changes. No CDN or network request is needed at runtime.

The public contracts do not provide a cause-specific nonfatal HE damage event. Health loss and nearby explosions are not treated as proof of a grenade hit, so no HE avatar animation is inferred.

## Optional metadata and media

The v3 session's typed options supplement game data with `players[steamId]` names/avatars and `match.left/right` IDs/Steam IDs. Immutable option records omit camera data. Names, team identities and scores remain governed by the current managed match and snapshot.

Options arrive atomically through the SDK-owned v3 session, with source-generated JSON metadata for trimming. Production does not poll `/hud-browser/options` or open a second panel stream. Both team IDs must match the active managed match; source session/match/team changes clear old metadata. A disconnect clears all SDK domains before a new complete baseline. The former bounded v2 metadata poller remains only as a legacy test fixture.

User-provided images must be valid `/cast-media/` paths resolved by the public SDK. Bundled game artwork is loaded from the installed package's local `assets/` directory. No remote cameras, arbitrary image URLs, cloud tokens, CDN fonts, tracking or personal credentials are used. Player portraits use the side/slot agent on failure where available. Failed live team logos are omitted; other presentation images use neutral monograms. An unavailable weapon image retains its text label.

GSI/HLAE player and source side names are decoded once for entities, then rendered as ordinary escaped text. Managed library/profile and operator texts are left unchanged. The HUD never treats a source name as HTML.

The HUD is GPL-3.0-only from 0.4.0; the public SDK remains MIT. Original Boltobserv source/maps and map-specific notices are included in `LICENSES/`. Original Valve artwork retains separate copyright terms; provenance, exact source entries and hashes are included in `LICENSES/VALVE-ASSETS.md` and `LICENSES/valve-assets.json` and shipped with the package.

## Lifecycle and presentation limits

One SDK-owned v3 session serves every scene, including game state, panel, options and manager views. The SDK validates revisions and complete baselines, handles reconnects and delivers live panel actions after state commit. Lower-third actions require the expected section/name/value; a disconnect or new source session clears transient production state. Independently subscribed regions ignore unrelated dependencies. Radar death positions reset for a new session/map/round/freezetime/timeline; a restarted or backwards HLAE timeline cannot silently supply old movement.

Visible timed regions subscribe to the official synchronized server clock. Round/bomb countdowns use the SDK helper with original source timestamps; paused/stale values remain fixed and missing anchors stay unavailable. The planned-start display uses the explicit managed start timestamp and server time; it does not assert that the match actually started. An eight-second killfeed lifetime is a presentation duration, not a reconstructed game-time event stream.

Successful synthetic/browser tests remain separate from native CS2/OBS capture, long-session performance and complete real-world source coverage.
